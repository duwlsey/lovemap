# Love Map

React + Vite로 만든 두 사람의 애정 지도입니다. 외부 저장소에 연결하기 전, 브라우저에서 회원 등록·개인 PIN 입장과 앱 기능을 확인할 수 있습니다. 저장소는 Google Sheets + Apps Script로 연결할 예정이며, 앱에서 Supabase를 호출하지 않습니다.

## 실행

배포와 Google 저장소 연결 순서는 [DEPLOYMENT.md](DEPLOYMENT.md)에 정리했습니다. GitHub Pages 배포 경로는 `/lovemap/`이며 배포 작업은 수동 실행입니다.

Node.js 설치 후 `npm install`, `npm run dev`를 실행합니다. 빌드는 `npm run build`, 기능 검증은 `node --test tests/*.test.js`입니다.

## 두 사람의 시작

1. 첫 사람이 **새로 시작하기**에서 이름, 개인 PIN 4자리, 연결 코드 4자리, 사귀기 시작한 날을 정합니다.
2. 개인 복구 코드를 따로 보관합니다. 복구 코드는 상대방에게 알려주지 않습니다.
3. 상대방은 **상대방 연결하기**에서 자신의 이름과 개인 PIN을 정하고, 첫 사람이 알려준 연결 코드를 입력합니다.
4. 두 사람이 연결되면 연결 코드는 만료됩니다. 사귄 날짜는 첫 사람이 설정한 날짜를 공유합니다.
5. 다음 입장에서는 등록된 기기에 기억된 계정의 PIN만 입력합니다. 같은 브라우저에 두 계정이 있는 경우 계정을 골라도 각자의 개인 PIN이 필요합니다.
6. 왼쪽 아래 계정 설정 또는 오른쪽 위 메뉴에서 PIN 변경, 복구 코드 재발급, 로그아웃을 할 수 있습니다. 연결 전에는 연결 코드 재발급도 가능합니다.

개인 PIN은 연결 코드와 달라야 하며 같은 커플의 상대 PIN과도 달라야 합니다. 다른 커플의 PIN과 전역 중복 검사하지 않습니다. 개인 PIN 변경·복구는 본인의 다른 세션만 만료시키고 상대 계정은 유지합니다. 잘못된 PIN을 다섯 번 입력하면 해당 계정은 5분간 대기합니다.

## 저장·연결 상태

- 계정: `love-map-pin-accounts-v1`. PIN은 개별 salt와 PBKDF2-SHA256 600,000회 해시로 저장하고 복구 코드는 해시만 저장합니다.
- 세션: 탭별 sessionStorage에 보관하며 12시간 후 PIN을 다시 요청합니다.
- 앱 내용: 커플별 `love-map-pair-state:<pairId>`. 두 계정이 같은 커플 공간에서 각자의 답변·점수·읽음 기록을 가집니다.
- 질문·미니게임: 커플 ID별 저장소를 사용합니다.
- 미리보기: 실제 계정·기록과 분리하고, 이름은 여보·자기, 사귄 일수는 1일째입니다.

**브라우저 저장소를 사용하는 로컬 시제품입니다.** 같은 브라우저에서 두 계정의 흐름을 확인할 수 있지만, 서로 다른 기기에서 연결·복구하려면 공통 서버 연결이 먼저 필요합니다. 로컬 PIN·해시·입력 제한은 개발자 도구로 저장소에 접근할 수 있는 사람에 대한 보안 경계가 아닙니다. 실제 서비스에는 서버 측 인증과 권한 확인을 구현해야 합니다.

`apps-script` 폴더의 질문·대시보드 코드는 추후 연결용입니다. 남아 있는 이전 Google ID 토큰 인증은 PIN 세션 인증으로 교체한 뒤에만 배포해야 합니다. 실제 시트 생성·배포·외부 전송은 수행하지 않았습니다. 기존 `supabase/schema.sql`과 이전 로컬 기록은 삭제하거나 새 계정에 자동으로 가져오지 않습니다.
