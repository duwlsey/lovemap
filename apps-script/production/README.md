# 최신 PIN 방식 서버 설치

이 폴더의 `Code.gs` 하나만 Apps Script에 붙여 넣습니다. 상위 폴더의 과거 Google 로그인용 `.gs` 파일을 함께 넣지 않습니다. `Code.gs`는 `npm run build:server`로 생성합니다.

## Google에서 한 번 할 일

1. 저장용 Google 스프레드시트에서 **확장 프로그램 → Apps Script**를 엽니다.
2. 기본 `Code.gs` 내용을 지우고 이 폴더의 `Code.gs` 전체를 붙여 넣고 저장합니다. 다른 `.gs` 파일은 필요 없습니다.
3. 왼쪽 **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 이름 `SPREADSHEET_ID`, 값은 저장할 스프레드시트 주소의 `/d/` 다음부터 `/edit` 앞까지의 ID를 입력합니다.
4. 편집기로 돌아와 함수 목록에서 **setupLoveMap**을 선택하고 실행합니다. Google 계정으로 권한을 승인합니다. 비공개 시트는 소유자 계정으로 접근합니다. 설치 함수는 서버 비밀 값 `AUTH_SECRET`을 자동으로 생성하며 기존 값을 바꾸지 않습니다.
5. 오른쪽 위 **배포 → 새 배포 → 유형 선택 → 웹 앱**을 선택합니다. **실행 사용자: 나**, **액세스 권한: 모든 사용자**로 설정합니다. 여기서 모든 사용자는 API 주소에 요청할 수 있다는 뜻이며, 개인 기록을 읽으려면 서버가 발급한 유효한 개인 세션이 필요합니다. 시트 자체의 공유는 비공개로 유지합니다.
6. 배포 후 표시되는 **웹 앱 URL**(`/exec`로 끝남)을 앱 연결에 사용합니다. 이 URL은 비밀번호가 아니며 브라우저에 공개됩니다.

Google의 권한 승인 화면은 소유자가 직접 진행해야 합니다. 프로젝트에 요청하는 권한은 스프레드시트 접근입니다. 새 프로젝트의 미확인 앱 안내가 나오면 자신이 붙여 넣은 코드와 요청 권한을 확인하고 진행합니다.

## GitHub에서 연결

저장소 Settings → Secrets and variables → Actions → **Variables**에 `VITE_APPS_SCRIPT_URL`을 만들고 웹 앱 URL을 넣습니다. 이후 Settings → Pages의 Source를 GitHub Actions로 선택하고 Actions → Deploy to GitHub Pages → Run workflow를 실행합니다.

서버 코드를 수정하면 Apps Script에 새 코드를 저장한 뒤 **배포 → 배포 관리 → 수정 → 새 버전**으로 같은 배포를 갱신합니다. 코드를 저장하기만 하면 게시된 서버는 바뀌지 않습니다.

## 데이터 구조와 확인

`LoveMapData`에는 kind, id, version, part, parts, data_json 열을 사용합니다. auth는 계정·커플·세션·실패 제한, pair는 알아가기·점검 결과·메모·읽음 상태·애정 지도 게임, asking은 질문 순서와 두 답변, dashboard는 오늘의 질문·답변·미니게임을 저장합니다. 긴 JSON은 셀 제한보다 작게 나누고 최근 두 저장본을 보존합니다. 시트의 행과 버전 번호를 직접 수정하지 않습니다.

개인 PIN은 서버의 비밀 키와 개별 salt로 HMAC-SHA256 검증값을 저장합니다. 서버 비밀 키는 시트나 공개 소스에 포함하지 않습니다. 세션·복구 코드·연결 코드도 원문을 시트에 저장하지 않습니다. 잘못된 PIN 5회는 5분 대기, 세션 12시간, 연결 코드 하루 만료, 연결 완료 시 코드는 소멸합니다. 비밀 키를 삭제·변경하면 기존 인증 정보가 무효화되므로 별도 보관합니다.

로컬 검사에서는 두 회원·다른 커플·새 기기를 각각 분리해 저장·권한·추첨·게임을 검증합니다. 실제 배포 URL을 받은 뒤에는 휴대폰과 컴퓨터의 가입·연결·기록 공유를 추가로 확인해야 합니다. 개발용 계정과 미리보기 기록은 업로드하거나 이전하지 않습니다.
