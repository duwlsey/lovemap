# 대시보드 기능과 저장 구조

지금은 외부 서비스에 연결하지 않습니다. 실제 모드는 `love-map-dashboard-v1`, 미리보기는 분리된 `love-map-preview-dashboard-v1` 브라우저 저장소를 사용하고, `makeAppsScriptDashboardStore`는 향후 연결을 위한 동일 인터페이스입니다. 서로 다른 기기 사이의 실시간 동기화는 아직 연결하지 않았습니다.

## 화면

- 상단 기존 문구와 궤도 그림 유지, 이어서 탐험하기 버튼 제거.
- 알아가기 업데이트: 수정 시각이 읽은 시각보다 새로운 카테고리 표시. 클릭하면 해당 카테고리로 이동하며 읽음 기록 저장.
- 오늘의 질문: 상대방의 이번 달 최신 점검에서 명시적으로 X인 항목을 질문 문장으로 변환. 하루 한 질문.
- 오늘의 답변: 상대방이 오늘 제출한 질문 원문과 답변. 지난 날짜의 답변을 오늘 답변으로 표시하지 않음.
- 세 달 점검 그래프: 돌아보기로 이동.
- 기록 열어보기: love box로 이동.
- love game: 택택토, 오목, 펀치기계. 애정 지도 게임하기는 기존 게임하기 탭으로 이동.

## 질문 순서

서울 날짜 기준. 최신 점검일을 시작일로 하며 접속하지 않은 날도 포함하여 하루씩 진행합니다. 미답변 항목은 순서의 맨 뒤로 이동하고, 답변을 완료한 항목은 현재 주기에서 제외합니다. 새 달에는 이전 달의 X를 가져오지 않습니다. 같은 달에 더 최신 점검이 생기면 그 최신 X 목록으로 바꾸되, 이미 답변한 당일에는 두 번째 질문을 내지 않습니다. 모든 항목을 답했거나 X가 없거나 이번 달 점검이 없으면 질문이 없다고 표시합니다.

`queues[사람]`: month, version, remaining(질문 번호), day, activeId, answered.

`replies[]`: id, author, recipient, questionId, question, text, date, sourceVersion.

`readUpdates[사람][카테고리]`: 읽은 답변의 수정 시각. 새로운 수정 시각이 들어오면 다시 알림 표시.

## 게임 규칙과 저장

`games[종류]`: id, kind, revision, turn, board, scores, winner, finished, winningCells.

세 게임 모두 첫 수나 첫 점수를 먼저 제출한 사람이 시작합니다. 빈 게임에는 고정된 선공이 없으며, 시작한 뒤에는 차례를 번갈아 진행합니다. 택택토는 3×3, 오목은 15×15이며 다섯 개 이상 연결하면 승리합니다. 보드에서 수를 고르고 상대에게 넘기기를 눌러야 저장됩니다. 상대 차례, 이미 놓인 자리, 이전 버전의 화면에서 오는 요청은 거부합니다. 펀치는 0–1000 왕복 막대를 START로 시작하고 PUNCH로 멈춘 뒤 상대에게 넘기기를 누릅니다. 두 점수가 모이면 높은 점수가 승리하며 같은 점수는 무승부입니다.

`pendingResults[사람][종류]`: 각자가 아직 보지 않은 완료 결과. 먼저 결과를 닫으면 현재 게임은 초기화하지만 상대방의 결과는 남겨둡니다. 상대도 자기 화면에서 WIN/LOSE/DRAW를 확인할 수 있습니다. 진행 중 바깥을 눌러 닫아도 이미 저장한 수는 유지됩니다.

미리보기에서는 대시보드의 좌측 여보·자기 선택 또는 게임 하단 계정 전환으로 두 사람의 동작을 확인합니다. 실제 연결 시에는 인증된 계정의 이름을 사용하며 전환 버튼은 표시하지 않습니다.

## Apps Script 연결 준비

- `DashboardDomain.gs`는 `src/services/dashboard-domain.js`에서 export만 제거한 동일 규칙입니다. 두 파일 일치는 테스트로 확인합니다.
- `Dashboard.gs`가 `Code.gs`의 인증·잠금 처리 아래에서 대시보드 요청을 처리합니다.
- 추후 `setupLoveMapDashboard`를 실행하면 DashboardEvents(id, data_json), CheckInResults(id, person, data_json)를 만듭니다.
- CheckInResults의 data_json은 `{date:"YYYY-MM-DD",created_at:"ISO timestamp",score:0,answers:{"0":false,...}}` 형태입니다. 기존 점검 저장 기능의 Google Sheets 전환 시 이 시트에 기록하도록 연결해야 합니다.
- 각 요청은 서버가 확인한 사람의 이름과 서울 날짜를 사용합니다. 클라이언트가 보낸 이름이나 점검 기록을 신뢰하지 않고 서버의 CheckInResults에서 읽습니다.
- 이벤트 하나를 한 행에 저장한 뒤 동일 규칙으로 재생합니다. 요청 ID 재시도는 중복 수나 답변을 만들지 않습니다. 동시에 들어오는 수는 Script Lock과 게임 revision으로 순서를 확인합니다.
- 화면 갱신은 현재 브라우저의 storage 이벤트와 focus에서 처리합니다. 향후 다른 기기 연동 시 원격 저장소의 주기적 조회도 연결해야 합니다.

실제 시트 생성·배포·계정 인증·기기 간 조회는 아직 수행하지 않았습니다. 이번 기능에서는 Supabase를 사용하지 않습니다. 기존 알아가기·점검 데이터는 앱이 전달하고 있으며, 그 저장소 전체의 Google Sheets 전환은 추후 연결 작업입니다.
